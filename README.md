# Офис программистов

Команда агентов-разработчиков под управлением из единого центра. Человек ставит
задачу — диспетчер Kristina отдаёт её нужному агенту, агент **предлагает**
действие, а единый шлюз решает: исполнить сразу или отправить на одобрение
человеку. Всё фиксируется в провенансе и видно в командном центре.

Модель — по образцу Palantir: контроль живёт не в агентах, а в чокпоинте, через
который проходят все изменения.

## Ключевая идея

> Агент не исполняет действия. Он только предлагает Действие из каталога
> онтологии. Тир риска и легальность определяет онтология, а не агент.

Поэтому агенты сменяемы, политику видно глазами (а не только в коде), а запись
файлов и коммиты по умолчанию проходят через человека.

## Быстрый старт

```bash
cd office
python -m pytest -q                    # 29 тестов

export WORKSPACE_ROOT=~/Projects/syndi-vercel    # подключение к проекту
export LLM_BASE_URL=...  LLM_API_KEY=...  LLM_MODEL=...   # AITunnel

uvicorn action_service:app --port 8000  # шлюз + исполнитель
uvicorn office_server:app  --port 8100  # офис (Kristina)
# в app/: npm run dev                    # командный центр на :5173
```

Без `WORKSPACE_ROOT` исполнитель работает как заглушка (ничего не пишет на диск).

## Из чего состоит

- **Бэкенд** (Python): онтология, шлюз действий, агенты, диспетчер, исполнитель.
- **Командный центр** (`web/` → секции для `kristina_agent_center/app/`):
  задачи, очередь одобрений, провенанс, штат, политика.
